# stm32_com_port — настройка CubeMX

Развёрнутое описание настроек CubeMX, от которых зависит работа STM32-части библиотеки. Краткая
сводка — в разделе «Требования к настройке в CubeMX» файла [README.md](README.md).

Названия параметров даны по CubeMX 6.x для STM32F4 (основная серия) и H7; в других сериях и
версиях CubeMX формулировка может немного отличаться, смысл настройки тот же. Библиотека сама
периферию не настраивает: она использует USB CDC, созданный CubeMX, поэтому все настройки
делаются в CubeMX до генерации кода.

## USB_OTG_FS / USB_OTG_HS

Раздел `Connectivity`. Настраивается тот порт, по которому идёт обмен. Для обмена по двум портам
настраиваются оба.

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| Mode | `Device_Only`, `Host_Only`, режимы OTG | `Device_Only` | STM32 выступает устройством, а компьютер — хостом. В других режимах COM-порт у компьютера не появится |
| Activate_VBUS (VBUS sensing) | включено, выключено | включить, только если линия VBUS разведена на вывод контроллера (FS: `PA9`, HS: `PB13`); иначе выключить | Контроллер по VBUS узнаёт, что кабель подключён. Если разрешить контроль, а VBUS на вывод не заведён, устройство никогда не подключится к компьютеру |
| Speed | FS: `Full Speed 12MBit/s`; HS: `High Speed 480MBit/s` или `Full Speed 12MBit/s` | FS-порт: `Full Speed`; HS-порт с внутренним FS-приёмопередатчиком: `Full Speed`; HS-порт с внешней микросхемой ULPI: `High Speed` | Определяет размер пакета USB: 64 байта в режиме Full Speed, 512 байт в High Speed. Для кадров до 1 КБ при частоте до 100 Гц достаточно Full Speed |
| Physical interface (PHY) | `Internal Phy` (FS); для HS-порта `Internal FS Phy` или `External ULPI Phy` | по тому, как физически подключён порт на вашей плате | Выбор неверного приёмопередатчика даёт полное отсутствие связи |
| Enable internal IP DMA (только HS) | включено, выключено | выключено | Библиотека отдаёт USB собственный буфер кадра; с DMA на ядрах с кэшем (F7, H7) буфер пришлось бы выравнивать и очищать кэш. Без DMA этого не нужно |
| Low power | включено, выключено | выключено | Режим пониженного энергопотребления (LPM) приостанавливает USB и может обрывать обмен |
| Signal start of frame (SOF) | включено, выключено | выключено | Вывод сигнала начала кадра на вывод. Библиотеке не нужен |
| Use dedicated end point1 interrupt | включено, выключено | выключено | Отдельное прерывание для одной из конечных точек. Библиотека рассчитана на общее прерывание USB |

## USB_DEVICE (класс CDC)

Раздел `Middleware` -> `USB_DEVICE`.

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| Class For FS IP (для порта FS) | список классов | `Communication Device Class (Virtual Port Com)` | Класс CDC делает из STM32 виртуальный COM-порт. Без него в `usbd_cdc_if.c` не будет функций `CDC_Transmit_FS` / `CDC_Receive_FS`, которые использует библиотека |
| Class For HS IP (для порта HS) | список классов | `Communication Device Class (Virtual Port Com)` | То же для порта HS (функции с суффиксом `_HS`) |
| Размер приёмного буфера CDC (`APP_RX_DATA_SIZE` в `usbd_cdc_if.h`) | не меньше размера пакета USB, верхняя граница — свободная ОЗУ | не меньше 64 для FS и не меньше 512 для HS; значение CubeMX по умолчанию (1000) подходит | В этот буфер USB складывает очередной принятый пакет перед вызовом `CDC_Receive_FS`. Меньше размера пакета нельзя: данные будут потеряны |
| Размер передающего буфера CDC (`APP_TX_DATA_SIZE` в `usbd_cdc_if.h`) | любое | значение по умолчанию | Библиотека передаёт USB свой буфер кадра, поэтому этот размер на её работу не влияет |
| Device Descriptor: VID, PID | любые 16-битные значения | значения CubeMX по умолчанию (ST: `0x0483` / `0x5740`) или ваши | Windows 10/11 для устройства класса CDC сама подключает встроенный драйвер `usbser`; устанавливать драйвер вручную не нужно. Linux подключает `cdc_acm` |
| Device Descriptor: строки (Manufacturer, Product, Serial) | любые | любые | Показываются в «Диспетчере устройств». Для работы библиотеки не важны |
| USBD_SELF_POWERED | `Enabled`, `Disabled` | по способу питания вашей платы | Только заявляет компьютеру тип питания, на работу библиотеки не влияет |

## Clock Configuration

Для USB требуется тактовая частота ровно 48 МГц, отдельная от основной шины. Допуск USB Full
Speed — около 0,25 %: этого может не обеспечить внутренний RC-генератор, поэтому рекомендуется
кварцевый резонатор.

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| Частота USB (в схеме `Clock Configuration`: `48MHz clocks`, на F4 это выход PLLQ) | 48 МГц, допуск около 0,25 % | ровно 48 МГц; формула: `F_VCO / PLLQ = 48 МГц` | Пример для F4 с кварцем 8 МГц: PLLM = 8, PLLN = 336, PLLP = 2 (SYSCLK 168 МГц), PLLQ = 7, откуда 336 / 7 = 48 МГц |
| Источник тактирования (HSE или HSI) | HSE (кварц), HSI | HSE | Внутренний HSI на F4 недостаточно точен для USB. На сериях со встроенным HSI48 (например, H7) его можно использовать, если включена система подстройки частоты по сигналу SOF (CRS) |
| Частота шины AHB (HCLK) | FS: не менее 14,2 МГц; HS: не менее 30 МГц (по справочному руководству) | в десятки МГц и выше | Нижняя граница нужна для работы ядра USB; типовые настройки (84-168 МГц на F4) её перекрывают |

Если CubeMX выделил частоту USB красным или показывает не 48 МГц, USB работать не будет.

## NVIC

Раздел `System Core` -> `NVIC` (вкладка `NVIC Interrupt Table`).

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| USB On The Go FS global interrupt (порт FS) | включено, выключено | включено | Прерывание, в котором HAL принимает пакеты USB и вызывает `CDC_Receive_FS`. Без него приёма нет. Обычно CubeMX включает его сам при выборе класса CDC |
| USB On The Go HS global interrupt (порт HS) | включено, выключено | включено | То же для порта HS |
| Preemption Priority | 0..15 (для F4: 4 бита) | любой | Библиотека потокобезопасна при любых приоритетах: общие данные защищены короткими критическими секциями. Прерывания с более высоким приоритетом могут вызывать `SCOM_Send` и `SCOM_GetRx` |
| Generate IRQ handler, Call HAL handler (столбцы Code generation) | включено, выключено | включено оба | Без них CubeMX не создаст обработчик прерывания, который вызывает `HAL_PCD_IRQHandler`, и USB не заработает |

## Системный таймер HAL

Раздел `System Core` -> `SYS`.

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| Timebase Source | `SysTick` или один из таймеров | `SysTick` (по умолчанию) | Библиотека берёт время для тайм-аутов из `HAL_GetTick()`, значит `HAL_IncTick()` должен вызываться по прерыванию. Приоритет этого прерывания на работу не влияет: библиотека не использует `HAL_Delay` |

## Память

Раздел `Project Manager` -> `Project` -> `Linker Settings`.

| Параметр в CubeMX | Допустимые значения | Рекомендуется | Пояснение |
|---|---|---|---|
| Minimum Heap Size | любое | не менее `0x400` для проектов, где USB-стек CubeMX выделяет память через `malloc` (старые версии пакета); в новых версиях выделение статическое | Нехватка кучи при инициализации USB приводит к тому, что устройство не появляется у компьютера |
| Minimum Stack Size | любое | значение по умолчанию (`0x400`) | Библиотека использует небольшой стек: больших локальных массивов в ней нет |
| Свободная ОЗУ | — | на каждый экземпляр библиотеки `3 * SCOM_MAX_PAYLOAD_SIZE` байт плюс служебные поля (около 3,1 КБ при 1024) | Память выделяется статически; число экземпляров задаётся `SCOM_MAX_INSTANCES` (по умолчанию 2) |

## Два USB-порта одновременно

Чтобы работали два экземпляра (по USB FS и по USB HS), в CubeMX настройте оба порта:

- в `Connectivity` включите `USB_OTG_FS` и `USB_OTG_HS` (оба `Device_Only`);
- в `USB_DEVICE` выберите `Communication Device Class (Virtual Port Com)` и для `Class For FS IP`,
  и для `Class For HS IP`; в `usbd_cdc_if.c` появятся функции с суффиксами `_FS` и `_HS`;
- в `NVIC` включите прерывания обоих портов;
- для HS-порта с внутренним FS-приёмопередатчиком отдельная частота не нужна (используются те
  же 48 МГц), для HS с внешней ULPI — тактирует микросхема-приёмопередатчик.

## Что настраивать не нужно

- Скорость, число бит и чётность виртуального COM-порта: они задаются программой на компьютере
  и игнорируются устройством, обмен идёт на скорости шины USB.
- DMA, UART, GPIO для линий USB: выводы `DM`/`DP` (`PA11`/`PA12` на F4 для FS) CubeMX
  настраивает сам при включении USB.
